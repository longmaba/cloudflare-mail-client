<Aside type="caution" title="Upstream reference: use the guided installer">

This page retains upstream Doota implementation details and historical commands.
For this fork, follow the [current guided setup](https://github.com/longmaba/cloudflare-mail-client#install) using Node 24, pnpm 10
and `pnpm run setup`; use `pnpm run doctor` for read-only diagnostics and
`pnpm run upgrade` for published releases. Native sending requires Workers Paid.
The installer preserves the selected account, domain, resource names and keys.
Older direct-deploy and automatic-deploy instructions below are historical reference,
not the installation path for a saved instance. See [current operations](https://github.com/longmaba/cloudflare-mail-client/blob/main/docs/OPERATIONS.md)
and the [staged pilot guide](https://github.com/longmaba/cloudflare-mail-client/blob/main/docs/KIENG-PILOT.md).

</Aside>

Doota involves two **different** Cloudflare tokens with different jobs. Don't
reuse one for the other:

| Token | Who uses it | When |
| --- | --- | --- |
| **Deploy token** (`CLOUDFLARE_API_TOKEN`) | Alchemy / CI | Deploy time only — creates and updates Workers, database, storage, queues. Scopes are listed in [Deploy](/self-hosting/deploy#b-archived-upstream-automatic-deployment). Local deploys don't need it at all (browser sign-in). |
| **App runtime token** (`APP_CLOUDFLARE_API_TOKEN`) | The running web app | When an org onboards a mail domain. **This page is about this token.** |

This fork uses the selected existing zone and configured mail domain. The
runtime token reads zone state and configures scoped MX/SPF/DKIM/DMARC and
literal recipient rules; apex catch-all changes require deliberate cutover. This is the **only** place the
app touches the CF API — never on the inbound hot path or during login.

<Aside type="danger" title="Never use the Global API Key">
  Use a **scoped API token** (a Bearer token). The Global API Key grants full
  account access and cannot be scoped down — a leak would compromise your entire
  Cloudflare account. Doota reads a token, not the Global Key, by design.
</Aside>

## Create the token

<Steps>
  <Step title="Open the token page">
    In the Cloudflare dashboard: **My Profile → API Tokens → Create Token →
    Create Custom Token**.
  </Step>
  <Step title="Grant the permissions below">
    Add each permission at the scope noted. Restrict **Zone Resources** to the
    account (or specific zones) that will host Doota domains.
  </Step>
  <Step title="Store it as a secret">
    Copy the token once — it's shown only at creation — and enter it at
    the masked runtime-token prompt in `pnpm run setup`. The installer saves
    it in private `.local/secrets.json` and reuses it — the deploy binds it
    to the web Worker. Never commit it.
  </Step>
</Steps>

## Required permissions

Restrict the runtime token to the selected existing zone. It is separate from
the account-scoped deployment token. Match Cloudflare's current permission
labels to the [current credential table](https://github.com/longmaba/cloudflare-mail-client#credentials-and-activation).

| Permission | Scope | Why |
| --- | --- | --- |
| Zone Read | Selected zone | Read zone status |
| DNS Edit | Selected zone | Configure scoped routing and sending DNS |
| Email Routing Rules/Settings Edit | Selected zone | Configure literal recipient rules; apex changes only after deliberate cutover |
| Email Sending Edit | Selected zone | Onboard the exact sending domain |
| Account Read / Email Sending Read | Selected account where required | Read account sending diagnostics |

The guided installer does not require all-zone runtime scope or new-zone
creation permission. Run `pnpm run doctor` to diagnose missing read scopes;
write permissions are exercised only by deliberate onboarding.

## The account ID

You also need your **Account ID** (`APP_CLOUDFLARE_ACCOUNT_ID`). Find it in the
dashboard on any domain's **Overview** page (right sidebar) or under **Workers &
Pages → Account details**.

## Rotation

Rotate the token if it may have leaked, and on a regular cadence for hygiene.
Create the replacement first, update the `APP_CLOUDFLARE_API_TOKEN` secret, then
revoke the old token — nothing on the mail hot path depends on it, so rotation
has no user-facing impact.
