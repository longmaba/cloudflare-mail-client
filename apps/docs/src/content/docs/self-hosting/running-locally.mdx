<Aside type="caution" title="Upstream reference: use the guided installer">

This page retains upstream Doota implementation details and historical commands.
For this fork, follow the [current guided setup](https://github.com/longmaba/cloudflare-mail-client#install) using Node 24, pnpm 10
and `pnpm run setup`; use `pnpm run doctor` for read-only diagnostics and
`pnpm run upgrade` for published releases. Native sending requires Workers Paid.
The installer preserves the selected account, domain, resource names and keys.
Older direct-deploy and automatic-deploy instructions below are historical reference,
not the installation path for a saved instance. See [current operations](https://github.com/longmaba/cloudflare-mail-client/blob/main/docs/OPERATIONS.md)
and the [staged pilot guide](https://github.com/longmaba/cloudflare-mail-client/blob/main/docs/KIENG-PILOT.md).

</Aside>

Get Doota running on `localhost` — no Cloudflare account required for the app
UI, auth, and the local D1 database. (Sending and receiving real mail needs a
deployed instance with a domain; see [Self-hosting](/self-hosting).)

## Requirements

- **Node 24**
- **[pnpm 10](https://pnpm.io)** (the repo is a pnpm workspace)
- A **Cloudflare account** — only needed later, for deploying and for real mail.

## Set up

<Steps>
  <Step title="Install dependencies">
    From the repository root:

    <PackageManagers type="run" args="install" />

    ```sh
    pnpm install
    ```
  </Step>

  <Step title="Create your env file">
    ```sh
    cp .env.example .env
    ```

    For local auth testing, also configure the selected development mail domain
    and a private setup token:

    ```sh title=".env"
    ORIGINS="http://localhost:5173"
    BETTER_AUTH_SECRET="<32+ random chars>"
    MAIL_DOMAIN="pilot.example.com"
    MAIL_ROUTING_MODE="manual"
    SETUP_TOKEN="<32+ random chars>"
    ```

    Generate a secret with:

    ```sh
    openssl rand -base64 32
    ```

    <Aside type="caution" title="ORIGINS must include your dev origin">
      better-auth trusts the origins listed in `ORIGINS`. If the port the dev
      server actually runs on isn't in the list, `/api/auth/*` returns 404.
      The dev server defaults to `http://localhost:5173` — include it with
      the protocol.
    </Aside>

    See [Configuration](/self-hosting/configuration) for every variable.
  </Step>

  <Step title="Apply database migrations">
    Create and migrate the local D1 database:

    ```sh
    pnpm db:migrate:local
    ```
  </Step>

  <Step title="Start the dev server">
    ```sh
    pnpm dev
    ```

    The app is now at [http://localhost:5173](http://localhost:5173).
  </Step>

  <Step title="Create the first domain administrator">
    Open the protected local `/setup?token=<your private SETUP_TOKEN>` wizard
    while the database has no users. Choose a login on `MAIL_DOMAIN`, a
    password and an external recovery address. The wizard initializes the
    pending organization and mailbox; it does not enroll TOTP or send mail
    before domain activation.

    Sign in at `/login`. Full onboarding requires a working configured
    domain, verified external recovery and authenticator TOTP for admins;
    local UI testing alone does not prove mail delivery.
  </Step>
</Steps>

<Aside type="caution" title="Recovery cannot create the first user">
  `reset-admin` only resets an existing superadmin. First-run provisioning
  always uses protected `/setup`; public registration is disabled.
</Aside>

## Handy scripts

| Script                     | Does                                       |
| -------------------------- | ------------------------------------------ |
| `pnpm dev`                 | Run the web app at `localhost:5173`        |
| `pnpm db:migrate:local`    | Apply D1 migrations to the local database  |
| `pnpm --filter doota db:studio` | Open Drizzle Studio                   |
| `pnpm check`               | Auth-boundary check + `svelte-check`       |
| `pnpm test`                | Run the Vitest suite                       |
| `pnpm --filter doota reset-admin` | Reset an existing superadmin only |
